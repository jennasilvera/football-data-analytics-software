# Commercial readiness assessment

The native software implementation has executable ingestion, research, model review, forecasting, intelligence, API, dashboard, persistence and container workflows. That establishes a reviewable product baseline. It does **not** establish validated predictive performance, a data license, a production SLO or customer-ready operations.

| Acceptance area | Implemented evidence | External release gate |
|---|---|---|
| Data correctness | Scope, entity, regulation-target and duplicate contracts; bitemporal revisions | Licensed feeds; actual publication/revision archives; real-source coverage audit |
| Reproducibility | Content identities, exact dependencies, safe model replay, temporal folds | Retained real source releases and independent reproduction |
| Forecast quality | Proper scoring rules, calibration, paired comparison, ablation and market joins | Untouched real-data evaluation; subgroup calibration; interval coverage and bias assessment |
| Intelligence | Rating/form/schedule/residual reports and next-match forecast lookup | Football-domain review; validated usefulness of trend/watch heuristics |
| Security | Shared bearer key, body limits, nonroot container, loopback defaults | TLS, user/tenant authorization, secret lifecycle, rate limits, security review |
| Reliability | Transactions, health checks, request logs, backup and recovery tests | Measured SLOs and capacity, off-host recovery drills, monitoring and incident owners |
| Legal/commercial | Source legal-use fields and explicit limitations | Counsel/provider permission for collection, model training and redistribution; support terms |

No paid data provider, public host, domain, external alert recipient, production identity provider or billing account is selected automatically. Those choices require actual access, contractual terms and operational ownership.

## Research limitations and remaining research work

Probability intervals and confidence categories remain unvalidated instead of invented. Poisson independence, calibration transfer to refit models, sparse national-team histories, manual/squad missingness, market coverage and block-dependence assumptions require real-data study. Historical confederation membership must be supplied with effective dates before claiming historical confederation results. Historical confederation frequency models, opponent-adjusted goal models and additional ranking-momentum signals are research extensions, not mislabeled implementations of the current global baseline.

The original professional upgrade sequence (ratings, models, calibration, integrations, reports, API, dashboard, containers, CI and governance documentation) is represented in executable native modules. The exhaustive feature wishlist is not evidence that every possible football signal is known or predictive. Typed input families support declared observations; unavailable fields remain missing. Optional Bayesian/neural models are not added without evidence they improve the declared evaluation.

## Release procedure

Retain a signed-off dataset/permission inventory, final holdout report, model card, deployment configuration, recovery drill and support owner. Record an explicit model release decision with its evidence. Reassess when sources, target definitions, competitions, features or infrastructure change. Do not market synthetic scores, source-hash matching or a passing CI badge as commercial validation.
